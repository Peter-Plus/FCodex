# 窗口模式：实现与验证（2026-10-19）

设置中的“窗口模式”保存在 localStorage；分栏、比例和标签归属只留在内存。重新启动准备一个 Codex 开始页。关闭模式保留 Codex/GPT 标签及独立的 Codex 空白草稿键，恢复原顶栏。已有系统窗口各自恢复普通布局。

顶栏保留 Logo、窗口新增入口和右侧控制；标签在独立的第二行。最多 4 栏，新增时每栏至少预留 320px，左右分隔线支持拖动和方向键。每栏同一时刻显示一个标签；关闭最后一个标签会关闭该栏，关闭整栏会关闭其中所有标签，剩余栏为空时建立一个 Codex 开始页。没有删除聊天记录的操作。

## 接入方式

- `src/window-layout.js` 管理临时归属，不保存聊天内容。
- `src/window-mode.js` 使用现有 Codex/GPT 标签协调器及原生路由。
- `startup/window-mode-patch.mjs` 对已锁定版本的 React 保留页面组件进行精确补丁。分栏中的页面在原生 React 树内显示；没有复制、跨文档移动或手动删除原生 DOM。分栏持有的页面不受后台 TTL 和容量淘汰影响，退出模式恢复原生策略。
- 每个 Codex 空白标签有独立原生 `homeDraftKey`。模式关闭后仍可从普通标签区切换。
- `startup/window-workspace-main.cjs` 校验主 frame、应用 URL、窗口注册、拖动令牌和标签类型；跨系统窗口迁移先导出路径、等待目标页面挂载，再关闭来源标签。失败优先保留来源；来源确认超时而目标已接收时保留目标，可能出现重复标签，避免丢失。
- 系统窗口由原生 window manager 创建，使用原生登录和会话初始化。新增系统窗口加载构建时打包的 Fade UI；它不播放启动动画。只有释放点位于所有应用窗口外时才创建系统窗口，内部无效放置及 Escape 不创建窗口。

## 当前边界，不能当作已完成的验收

跨系统窗口只迁移已保存、空闲的聊天或空白页。检测到未发送文字、附件、生成中状态，或无法确认 GPT 空闲状态时拒绝迁移并提示。**不支持带草稿、附件、生成中状态的无缝跨系统窗口迁移。** 同一应用窗口内部移动仍保留原生页面对象。

真实客户端的多栏并行输入、原生右侧工具/弹出菜单、冷启动、窗口缩放、多显示器及系统级拖出/拖回尚待验收。浏览器夹具和 IPC 模拟测试不证明这些实际行为已通过。当前未覆盖正在运行的 `.fade-runtime-isolated/app`。

浏览器截图和独立配置归入 `.work/review/test-runs/window-mode-*`，仅作证据，不是构建输入。失败运行同样保留供检查，不批量删除。首次使用需完整退出再从 Fade 入口启动，使主进程、preload 和原生页面补丁同时生效；旧运行时会拒绝开启窗口模式并提示重启。
